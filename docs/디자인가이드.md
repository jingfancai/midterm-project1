# 디자인 가이드 — Polarsteps v2

> 기획 5단계 "화면 기획"(발표자료 부록 B5 화면별 요소 분석표)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 순서로 같이 고칩니다.
> 현재 화면명과 위젯 구조를 Polarsteps v2에 맞춰 수정했습니다. 현행 앱 리뷰 근거와 원칙 카드는 실제 조사 후 채워야 합니다.

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 나의 여행 목록 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/items` |
| B | 여행 상세 | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A에서 카드 누름 | `/notes?itemId=` ('여행 기록' 탭) |
| C | 여행 추억 카드(임의) | `lib/screens/c_result_sheet.dart` | 덮기(modal) — B의 "결과 보기" | 없음(미리 정한 결과) |

```
A 나의 여행 목록 ──쌓기(push)──▶ B 여행 상세 [옆으로(tab): 여행 정보 | 여행 기록] ──덮기(modal)──▶ C 여행 추억 카드(임의)
```

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(tab) · **덮기**(modal) — 흐름도의 화살표마다 하나를 적는다.
- 적응형: A는 창 너비 **600dp 이상**이면 격자(GridView), 미만이면 목록(ListView) — `LayoutBuilder`.

## 2. 원칙 표 P01–P10 (P번호 = 닐슨 원칙 번호)

P번호 하나를 디자인 가이드 · 코드 주석(`// A-5 P09`) · 커밋(`p09: …`) · 영상(`p09.mp4`) · 발표 원칙 카드에 그대로 씁니다.
고친 원칙은 `docs/원칙카드.md`에 카드 한 장씩. 현행 앱이 이미 잘 지킨 원칙은 "해당 없음 + 이유"를 적습니다(점수 규칙 아님).

| P01 | 시스템 상태의 가시성 | | 예) A-4 · A-6 · B-7 | `grep -rn "P01" lib` | p01.mp4 | |

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### 여행 카드 목록
- **목적**: 사용자가 기록한 여행을 빠르게 찾아 선택하도록 한다.
- **내용**: 대표 사진, 여행 제목, 날짜·장소, 태그를 카드에 표시한다.
- **의도**: 사진과 제목을 먼저 보여 주어 여행을 쉽게 구분하도록 한다. 실제 리뷰 근거는 조사 후 추가한다.

## 5. 상태관리 포인트 (표시만 — 구현하지 않는다)
