# 디자인 가이드 — Polarsteps v2 중간 UI/UX Prototype

이 문서는 현재 제출용 A/B/C 화면, 요소 번호와 Nielsen 원칙의 기준이다.
예전 서버 쓰기·영구 저장·실시간 통계 확장 설명은 이 문서로 대체한다.
PPT 파일 자체는 저장소에 없으며, `자가평가.md`와 `셀프논증.md`에 적힌 발표자료 부록 B5 요구를 참고했다.
실제 앱 리뷰·발표 영상·교수의 최종 승인 근거는 아직 제공되지 않았으므로 만들어 적지 않는다.

## 1. 화면 목록과 흐름

| 화면 | 비즈니스 명칭 | 코드 | 진입 | GET |
|---|---|---|---|---|
| A | 나의 여행 목록 | a_list_screen.dart | 첫 화면 | /items |
| B | 여행 상세 | b_detail_screen.dart | A 카드에서 Navigator.push/pop | /notes?itemId= |
| C | 여행 추억 카드 | c_result_sheet.dart | A의 기록 모아보기에서 showModalBottomSheet | 없음; A의 읽기 전용 예시 카드 재사용 |

A → B는 쌓기, B 여행 정보/여행 기록은 옆으로(TabBar/TabBarView), C와 편집·추가·삭제 확인은 덮기(Dialog/BottomSheet)다.
프로필은 독립 화면이 아니다. A-1의 기존 아바타를 누르면 개인정보 없는 설명 Dialog를 연다.
B-6은 현재 여행의 고정 추억 카드 Dialog다. C는 A에서 여는 여행 회고 BottomSheet다.

## 4. 디자인 가이드 글

나의 여행 목록은 대표 사진과 여행 제목으로 항목을 알아보기 쉽게 한다. 사진 위 라벨과 버튼은 두지 않고,
사진 아래 제목 오른쪽에 즐겨찾기·삭제 아이콘을 둔다. 다음 줄은 날짜와 목적지다. 600dp 미만은 목록의
16:9 표지, 그 이상은 격자를 유지한다. 색상·카드 둥근 모서리·여백·사진 자원은 기존 디자인 그대로다.
B는 큰 표지 아래 20dp 간격을 두고 여행 정보를 표시한다. 실제 지도·인증·GPS·AI·추천 처리는 없다.

## 5. 상태관리 계획 — 구현하지 않는 업무 상태

| 계획 데이터 | 입력 요소 | 표시 계획 | 코드 위치 |
|---|---|---|---|
| 즐겨찾기 여부 | A-9/B-5 | 카드 아이콘·보관 상태 | a_list_screen.dart / b_detail_screen.dart |
| 새 여행·편집 결과 | A-11/B-8 | A 목록·B 제목 | trip_editor.dart |
| 삭제·복원 상태 | A-9 | A 목록 | a_list_screen.dart |
| 실제 검색·정렬 결과 | A-7/A-8 | 카드 목록 | trip_insights.dart |
| 여행 기록 추가 | B-7 | 타임라인 | b_detail_screen.dart |
| 실제 통계 | A-10/C-3 | 통계 카드 | trip_insights.dart / c_result_sheet.dart |

각 위치에 `// STATE:`를 남긴다. Provider/Riverpod/Bloc 등은 사용하지 않는다.
텍스트 입력, 탭 선택, 시연용 필터 장면, Dialog, GET 재시도는 StatefulWidget/setState의 로컬 표시 상태만 사용한다.
업무 상태를 저장하거나 다른 화면에 전파하는 상태관리 계층은 구현하지 않는다.

## 6. GET 전용 데이터와 원형 시연

HTTP는 lib/api.dart의 GET /items, GET /notes?itemId= 두 종류뿐이다. 일반 HTTP method를 받는
쓰기 함수나 생성/편집/삭제 API는 없다. 로컬 서버도 읽기 전용 메모리 라우터이며 DB에 쓰지 않는다.
추가·편집은 기존 TripEditor의 입력 Widget를 유지하고 완료 시 시연 SnackBar만 표시한다.
즐겨찾기·삭제·실행 취소도 원본 데이터를 변경하지 않는다. 취소 후/완료 후/새로고침 후에 같은 GET 예시가 남는다.

## 7. 통계와 여행 상태 예시

TripSummary의 4여행·1즐겨찾기·1예정·1진행·2완료·13일·2국가·4도시는 정해진 표시값이다.
도시/국가 중복 제거, 여행 기간 합산, 날짜 비교나 실시간 갱신을 하지 않는다.
예정/진행/지난 여행은 db.json에 미리 적은 demoStatus를 표시하며 날짜나 오늘 시점에서 계산하지 않는다.
예시 표시는 사용자 데이터와 무관함을 A-10/C-4에 명시한다. 이는 실제 방문 사실이나 추천 결과가 아니다.

## 8. 검색·정렬·국가 안내

어떤 검색어를 넣어도 같은 첫 여행 예시를 보여 준다. 즐겨찾기 필터도 같은 미리 정한 장면이다.
정렬 드롭다운은 선택 모양만 바뀌고 데이터 순서를 비교하거나 재정렬하지 않는다.
편집 폼의 국가 자동 인식 영역은 실제 인식 없이 고정된 시연 안내만 표시한다. 저장·국가 통계와 연결하지 않는다.
사진의 정적 목적지-URL 대응은 사진 표시 자원 선택 용도로만 유지한다.

## 9. 범위·개인정보·외부 서비스

별도 ProfileScreen을 제거하고 기존 A 아바타는 설명 모달로 처리한다. A/B/C 이외 독립 페이지는 없다.
로그인·회원가입·결제·개인정보 수집·유료 API·실시간 통신은 없다. 입력은 가상의 여행명·목적지·메모만 시연하며
저장·전송하지 않는다. 공개된 예시 여행 데이터만 GET으로 읽는다. 사진 CDN 접근은 기존 고정 사진 표시만 담당한다.

## 10. 데이터·사진 자원과 시험 범위

destinations.json의 50개 도시·35개 국가와 기존 지역 자료, 확인된 고정 사진·라이선스는 보존한다.
앱 시작 시 asset을 읽고 검증하는 것은 표시 자원 로딩이며 외부 지오코딩/추천 API를 호출하지 않는다.
알 수 없는 사진은 중성 표지로 대체하고 실패 시 기존 이미지 아이콘을 사용한다.
테스트는 사진과 반응형 레이아웃·A/B/C 이동·Loading/Error/Empty·GET 오류 복구·데이터 비변경 시연을 확인한다.
종전 영구 저장 및 실제 알고리즘 테스트 파일은 삭제/비활성화하지 않고 GET-only/고정 예시 계약으로 갱신한다.

## 11. 남은 확인 사항

실제 PPT, 앱 리뷰, 발표 영상은 제공되지 않아 일치 여부를 최종 확인하지 못했다.
단순 UI 로컬 상태·사진 이름 매핑·GET 파싱까지 교수의 '실제 로직' 범위로 보는지는 수업 기준 확인이 필요하다.
출처·허가 기록이 있는 외부 사진은 실제 개인정보 입력과 구분되며 네트워크 실패 시 중성 표지/아이콘이 표시된다.
정적 예시가 아니라 실제 기능이라고 발표하지 않는다. 최종 점수·승인은 교수의 판단이며 자동 테스트 통과와 별개다.
