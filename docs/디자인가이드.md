# 디자인 가이드 — Polarsteps v2

> 기획 5단계 "화면 기획"(발표자료 부록 B5 화면별 요소 분석표)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 순서로 같이 고칩니다.
> 현재 화면명과 위젯 구조를 Polarsteps v2에 맞춰 수정했습니다. 현행 앱 리뷰 근거와 원칙 카드는 실제 조사 후 채워야 합니다.

## 6. 여행 관리 확장 (사용자 요청)

기존 A 화면과 청록색 카드 스타일을 유지한다. 별도 화면이나 패키지를 추가하지 않는다.
사용자의 후속 명시적 요청에 따라 A-7–A-10의 여행 데이터를 json-server 파일 DB에 영구 저장한다.
기존 UI 템플릿의 GET 전용·영구 저장 금지 규칙은 이 요청의 여행 관리 기능에는 적용하지 않는다.
POST로 생성하고 PATCH로 편집·즐겨찾기·소프트 삭제·복원을 저장한다. HTTP 요청은 `lib/api.dart`에만 둔다.
서버 응답의 Item을 단일 데이터로 사용해 홈페이지와 상세 페이지를 동기화한다. 새로고침과 서버 재시작 후에도 DB에서 복원한다.

- 검색은 대소문자를 구분하지 않고, 공백으로 나눈 단어가 제목·날짜·목적지·태그에 모두 포함되는지 확인한다.
- 정렬은 기존 예정/진행/완료 그룹 안에 적용한다. 잘못된 날짜는 '날짜 미정' 그룹으로 분리한다.
- 여행일 합계는 각 여행의 시작일과 종료일을 포함한 기간의 합계다. 겹치는 기간도 여행별로 합산하고 날짜 미정은 제외한다. 실제 이동 거리나 방문 국가 수로 추정하지 않는다.
- 삭제 확인에서는 새로고침 후에도 삭제됨을 알리고, SnackBar에서 서버에 저장되는 실행 취소를 할 수 있다. 삭제한 여행은 회고에서도 제외한다.
- 카드의 즐겨찾기·삭제 버튼은 상세 화면을 열지 않는다. 검색 결과가 없을 때 검색·필터 초기화 버튼을 제공한다.
- 제목·목적지·국가·날짜 수정은 B-8의 공통 편집 폼에서 수행하며, 서버 저장 성공 후 상세·홈·검색·정렬·통계·회고에 반영한다. 저장 실패 시 입력과 기존 목록을 유지한다.

| 바뀌는 데이터 | 표시 위치 |
|---|---|
| 검색어·즐겨찾기 필터·정렬 | A-7 · A-8 → A-2 · A-3 · A-6 |
| 즐겨찾기 ID | A-9 → A-8 · A-9 · A-10 |
| 삭제 ID·제목 수정 | A-9 / B 제목 수정 → A 목록·회고·A-10 |

## 7. 영구 저장과 방문 국가 집계

- B-8 TripEditor: 여행 이름 → 목적지 → 국가 자동 인식 안내(Text) → 출발 날짜 → 종료 날짜 → 오류 안내 → 저장/취소.
- A-10 / C 회고 통계는 동일한 TripSummary를 사용한다. 국가 코드는 로컬 도시 대응표에서 자동 인식하며 같은 국가의 다른 도시·언어 표기를 중복 제거한다. 수동 입력값이나 오래된 국가 코드는 추정 근거로 사용하지 않는다.
- 국가 수는 시작일이 오늘 이하인 진행/완료 여행만 포함한다. 아직 출발하지 않은 미래 여행, 삭제된 여행, 날짜 미정, 잘못된 국가 코드는 제외한다.
- API 실패 시 데이터가 사라진 것처럼 표시하지 않는다. 오류를 알리고 기존 값을 유지하며 폼에서 재시도할 수 있다. 중복 저장은 진행 중에 차단한다.
- 로컬 JSON Server는 쓰기 모드와 영구 디스크가 필요하다. 기존 Vercel GET 전용 예시는 이번 저장 기능을 제공하지 않는다.

## 8. 목적지 자동 인식과 고정 사진

- B-8의 국가 입력 TextFormField를 제거하고 기존 목적지 입력 아래 Text 안내를 표시한다. 새 화면이나 사용자 정의 Widget 클래스는 추가하지 않는다.
- 도시 이름은 로컬 `assets/data/destinations.json`에서 영어·한국어·중국어 별칭으로 인식한다. 영어 대소문자와 공백은 정규화하되 전체 별칭이 맞아야 한다. 부분 문자열, 불명확한 도시 이름, 여러 도시를 쓴 입력은 추측하지 않는다.
- 예: Tokyo / 도쿄 / 东京 / 东京都 → 일본(JP), Osaka / 오사카 / 大阪 → 일본(JP), Paris / 파리 / 巴黎 → 프랑스(FR).
- 인식 실패 시 '국가를 인식하지 못했어요. 도시 이름을 확인해 주세요. 방문 국가 통계에서 제외됩니다.'라고 안내한다. 여행 자체는 저장할 수 있지만 국가 코드는 빈 값이고 방문 국가 수에 포함하지 않는다.
- 지원 범위: JSON asset에 관광 도시 50개·국가 35개를 수록한다. 기존 제주도·강원도는 호환용 지역 2개로 별도 보존하며 도시 수에는 포함하지 않는다. 전체 목록과 수정 방법은 `assets/data/README.md`를 참고한다. 전 세계 지오코딩 기능은 아니다.
- 도시 사진은 검토한 고정 Unsplash 이미지와 Wikimedia Commons의 CC0/공유영역 사진을 사용한다. 도시 50개와 별도 지역인 제주도에 목적지별 사진을 제공한다. 미인식 목적지와 사진 대응이 없는 지역은 중성 비행기·구름 기본 표지를 사용한다. 난수나 검색 API를 사용하지 않는다.
- `Item.photoUrl`을 홈·상세·상세의 다른 여행 썸네일·회고에서 동일하게 사용하고 기존 NetImage를 그대로 재사용한다. 기존 DB에 잘못된 사진이 있어도 목적지를 기준으로 표시를 수정한다.
- 저장 시 자동 인식한 국가 코드와 고정 사진 URL을 기존 POST/PATCH 데이터에 포함한다. 새로고침 후에도 같은 결과를 사용한다. 목적지를 수정하면 사진과 국가 통계가 함께 바뀐다.
- 방문 국가 집계는 기존 시작일 기준과 소프트 삭제 제외 규칙을 유지한다. 동일 국가의 도시는 한 번만 세고 미래 여행은 제외한다.

## 9. 방문 도시 수

- A-10의 기존 Chip과 회고의 기존 _StatCard를 재사용하여 '방문 도시 수'를 표시한다. 새 화면·Widget 클래스·의존성은 추가하지 않는다.
- 도시의 영문·한국어·중국어 별칭은 국가 코드와 명시적 cityId로 구성한 같은 cityKey를 사용한다. 예: Tokyo / 도쿄 / 东京는 JP/tokyo 하나이며 Osaka는 JP/osaka이므로 도시 2개·국가 1개다.
- 도시·국가 모두 이미 시작한 미삭제 여행만 집계한다. 미래·날짜 미정·미인식 목적지는 제외한다. 지도나 서버 호출 없이 기존 로컬 목적지 표를 사용한다.
- 강원도와 제주도처럼 대응표가 도/섬 단위로 인식하는 장소는 국가 집계에는 포함하지만 도시로 추정하지 않는다.
- 저장·수정·삭제·복원 시 같은 TripSummary에서 두 통계를 함께 갱신하며 검색·필터와 무관하게 전체 유효 여행을 집계한다.

## 10. JSON 목적지 목록

앱 시작 전 main()에서 목적지 asset을 한 번 읽고 검증한다. Dart에는 도시 목록을 두지 않으며
DestinationCatalog가 정확한 별칭 매칭과 불변 조회표만 제공한다. 파일에 도시·국가·3개 언어 이름·
별칭·선택 사진 URL을 함께 저장한다. 누락된 필수 이름, 별칭/ID 충돌, 잘못된 사진 URL은 검증 오류로
처리하여 조용히 잘못된 통계를 만들지 않도록 한다. 데이터 확대 외에 화면이나 Widget는 추가하지 않는다.

## 11. 목적지 사진 보완

사진 매핑만 확대하여 도시 50개와 제주도에 전용 사진을 지정했다. photoSource와
assets/data/PHOTO_SOURCES.md에 원본·라이선스·확인 기록을 보관한다. 일부 사진은 역사 사진이며
자료의 시대를 문서에 명시했다. 기존 NetImage는 사진 로드 실패 시 중성 기본 표지를 한 번만 시도하고,
기본 표지도 실패하면 기존 이미지 아이콘을 표시한다. 화면·Widget 클래스·통계·저장 로직은 추가/변경하지 않는다.

## 12. 여행 상세 간소화

B-3의 큰 현재 여행 표지는 유지하고 그 아래 다른 여행의 가로 썸네일 목록과 해당 목록용 조회·이동을 제거한다.
표지와 회고 안내 사이 간격은 20dp로 정리한다. 제목·날짜·장소·편집·즐겨찾기·여행 기록 기능은 유지한다.
새 화면이나 Widget 클래스는 추가하지 않는다.
