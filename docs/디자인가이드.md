# 디자인 가이드 — Polarsteps v2 중간 UI/UX Prototype

이 문서는 현재 A/B/C/E 화면, 요소 번호와 Nielsen 원칙의 기준이다.
최소 수정 요청에 따라 원래 상호작용·계산을 복구하되 서버 쓰기·영구 저장은 제거한다.
이 버전은 기능 보존안이며 교수 감점 규칙을 모두 충족한다고 주장하지 않는다.
AGENTS.md의 실제 로직·업무 상태 미구현 원칙과 달리, 사용자의 명시적 요청으로 아래 세션 기능을 유지한다. 위험은 11절에 기록한다.
PPT 파일 자체는 저장소에 없으며, `자가평가.md`와 `셀프논증.md`에 적힌 발표자료 부록 B5 요구를 참고했다.
실제 앱 리뷰·발표 영상·교수의 최종 승인 근거는 아직 제공되지 않았으므로 만들어 적지 않는다.

## 4. 디자인 가이드 글

나의 여행 목록은 대표 사진과 여행 제목으로 항목을 알아보기 쉽게 한다. 사진 위 라벨과 버튼은 두지 않고,
사진 아래 제목 오른쪽에 즐겨찾기·삭제 아이콘을 둔다. 다음 줄은 날짜와 목적지다. 600dp 미만은 목록의
16:9 표지, 그 이상은 격자를 유지한다.
A의 나의 여행 제목은 기존 글꼴·#183B3A·배치를 유지하고 24px·w800으로 표시한다.
A의 다가오는 여행 / 진행 중인 여행 / 지난 여행 그룹 제목은 24px·w800으로 강조하고 기존 진한 녹색(#183B3A)을 유지한다.
제목 옆 수량은 기존 13px·w600·#78908A와 8dp 간격을 유지하며, 날짜 미정 제목은 기존 19px을 유지한다. 색상·카드 둥근 모서리·여백·사진 자원은 기존 디자인 그대로다.
B는 큰 표지 아래 20dp 간격을 두고 여행 정보를 표시한다.
C는 통계 → 방문 장소 지도 → ALL MY TRIPS 순서다. Featured Memory(대표 여행)는 제거한다.
C 전체를 스크롤할 수 있어 작은 창과 긴 여행 목록에서도 지도·전체 기록·닫기에 접근할 수 있다. 외부 지도 서비스·인증·GPS·AI·추천 알고리즘은 없다. E는 고정 테마 목록만 표시한다.

## 6. GET 전용 데이터와 메모리 상호작용

HTTP는 lib/api.dart의 GET /items, GET /notes?itemId= 두 종류뿐이다. POST/PUT/PATCH/DELETE,
일반 HTTP method를 받는 쓰기 함수, 생성/편집/삭제 API가 없다. 로컬 서버도 읽기 전용 메모리 라우터이며 DB에 쓰지 않는다.
TripEditor 입력 검증 후 추가/편집 결과를 A/B의 메모리 콜백으로 전달한다. 새 여행에는 세션 전용 음수 ID를 부여한다.
즐겨찾기·삭제·실행 취소는 현재 세션 목록에만 반영된다. 삭제 SnackBar는 기존 알림을 정리하고 보통 4초,
접근성 설정 시 10초 동안 실행 취소를 제공한다. 새로고침은 GET 원본을 다시 읽어 세션 변경을 초기화한다.
앱 재실행/브라우저 새로고침도 변경을 잃는다. shared_preferences/파일/DB 등 로컬 영구 저장도 없다.

## 7. 여행 통계와 날짜 분류

TripDates와 오늘 날짜를 비교해 예정/진행/완료/날짜 미정으로 분류한다. TripSummary는 삭제되지 않은
현재 세션 여행 수·즐겨찾기 수·분류별 수·여행 기간 합계를 계산한다. 기간 합계에는 미래 여행도 포함되며
방문 도시/국가만 이미 시작한 여행으로 제한한다. 날짜가 잘못되거나 없는 여행은 방문 집계에서 제외한다.
한·영·중 별칭을 같은 도시 ID로 통합하고 도시/국가를 각각 중복 제거한다. Tokyo+Osaka는 2도시·1국가다.
제주도·강원도 같은 지역 항목은 국가 수에는 반영하지만 도시 수에는 넣지 않는 기존 정책을 유지한다.
추가·편집·즐겨찾기·삭제·복원 후 A 통계와 다시 연 C가 최신 메모리 데이터를 사용한다. 타이머나 실시간 통신은 없다.
이 계산은 실제 로직이므로 교수의 감점 위험이 남는다.

## 8. 검색·정렬·목적지 인식·사진

검색은 제목·날짜/목적지·태그에서 공백으로 나눈 모든 검색어를 대소문자 구분 없이 찾는다.
즐겨찾기 필터는 현재 메모리의 선택값을 사용한다. 정렬은 각 날짜 그룹 안에서 최신/과거 출발일/이름순을 적용한다.
목적지는 로컬 destinations.json의 한·영·중 도시 이름과 별칭으로 국가·도시 ID·고정 사진을 찾는다.
인식하지 못하면 한국어 안내와 중성 기본 표지를 쓰고 방문 도시·국가 집계에서 제외한다. 임의 국가 추측은 없다.
홈 카드는 Item.photoUrl과 기존 NetImage를 유지한다. B 상단 큰 사진은 B-10의 단일 슬라이드로 재사용한다.
B-10 슬라이드와 C-8 회고 카드는 사용자 메모리 사진을 우선 사용하고 없으면 같은 목적지 기본 사진을 사용한다. 랜덤 사진·외부 지도/지오코딩 API는 없다.
검색·정렬·집계·목적지 인식은 실제 처리이며 단순 UI 장면으로 가장하지 않는다.

### C-6 방문 장소 지도

세계 지도는 앱에 포함된 assets/images/world_map.png를 사용하며 Natural Earth 공개 도메인 육지 윤곽을
기존 녹색 톤으로 그렸다. 지도 타일·지도 API·GPS·지오코딩·새 네트워크 호출은 없다. 출처는 assets/images/README.md다.
전체 경도 -180~180, 위도 -90~90의 정거원통도법(Plate Carree)으로 PNG와 Marker를 같은 비율로 배치한다.
destinations.json의 50개 도시 모두 대략적인 도심 좌표를 갖는다. 이는 관광 도시 예시 위치이며 개인 위치가 아니다.
통계와 같은 isVisitedTrip 조건을 공유하며 이미 시작하고 날짜가 유효한 미삭제 여행만 표시한다.
한·영·중 이름은 기존 cityKey로 묶어 Marker 하나에 해당 여행 제목을 모은다. 같은 도시의 여러 여행은 하나의 점이다.
지역(제주도·강원도), 미인식 장소, 좌표 없는 장소는 도시 Marker로 추측하지 않는다. 지역은 기존 국가 통계 정책을 유지한다.
Marker가 가까이 겹치면 36dp 이내 도시들을 함께 Dialog에 보여 누락 없이 확인할 수 있다.
표시할 도시가 없으면 한국어 안내를 보여 준다. 세션 내 추가/수정/삭제 후 C 재진입 시 현재 데이터로 지도도 갱신한다.
InteractiveViewer로 1~8배 확대/축소·드래그를 지원한다. 배경과 Marker가 같은 변환 안에서 함께 움직인다.
확대·축소·초기화 버튼은 같은 지도 안에 있고 새 화면은 없다. 별도 화면·길찾기·경로 저장은 추가하지 않는다. C-7은 기존 AlertDialog와 Text/Column만 재사용한다.

### B-10 로컬 여행 사진 (순간을 다시 꺼내 보기)

순간을 다시 꺼내 보기의 기존 제목·사진 아이콘·설명 문구를 상단 큰 사진 바로 위로 옮긴다.
기존 큰 사진 위치에 PageView.builder를 두고 4:3 비율·22dp 모서리·18dp 좌우 여백을 유지한다.
시작한 여행의 페이지 수와 추가/교체/삭제 버튼은 사진 바로 아래에 둔다. 후기 아래의 중복 사진 패널은 제거한다.
사진은 여행당 최대 5장이다. 가로로 넘겨 현재 사진을 선택하고 페이지 수를 표시한다. 마지막 사진을 삭제하면
슬라이드에 목적지 매칭 기본 사진 1장이 표시된다. 이 기본 사진은 사용자 사진 5장 제한에 포함하지 않는다.
진행 중/종료 여행만 사진 추가·교체·삭제가 가능하다. 미래 여행은 사용자 사진이 메모리에 있어도 목적지 기본 사진만 표시하고 사진 관리/페이지 수를 숨긴다.
날짜 미정·오류 또는 삭제된 여행도 기본 사진과 날짜 확인 안내만 표시한다. canManageTripPhotos는 기존 방문/후기 조건을 공유한다.
선택 창이 열린 동안 날짜가 미래로 바뀌면 반환된 사진을 적용하지 않는다. 진행/종료 → 미래 변경 시 표시 페이지를 초기화하고,
기존 메모리 사진은 삭제하지 않는다. 다시 시작한 날짜로 바꾸면 첫 사용자 사진부터 표시한다. 기존 후기·추억 카드의 날짜별 제한은 바꾸지 않는다.

Web 파일 선택창에서 직접 고른 파일만 읽는다. 한 장 10MB 이하, 최대 60MP 소스를 허용하며 디코딩 후 긴 축 1920px
이하의 정적 PNG로 메모리 변환한다. 애니메이션은 첫 프레임만 사용한다. 잘못된 형식/손상/초과 선택은 한국어로 안내하고
현재 사진은 유지한다. 취소는 변경하지 않는다. 읽는 중 중복 작업은 막는다. 사진 경로·EXIF·파일명은 여행 데이터에 보관하지 않는다.

Item.photos는 메모리 바이트 목록이며 copyWith를 통해 A의 세션 데이터와 B/C에 전달한다. GET 응답에서 사용자 사진을 읽지 않고,
toJson에도 포함하지 않는다. 서버 업로드·POST/PUT/PATCH/DELETE·브라우저 저장소·파일 쓰기는 없다.
B 재진입/제목·날짜·Tag 편집/즐겨찾기 후에도 현재 세션 사진을 유지하고 GET 새로고침/앱 재실행 시 사라진다.
C 미리보기와 PNG는 첫 사용자 사진을 사용한다. 사용자 요청 PNG 다운로드는 기존 명시적 내보내기 예외만 적용한다.
네이티브 파일 선택 플러그인은 추가하지 않으며 기존 Web 데모 범위에서 선택을 지원한다. 네이티브에서는 안내 및 비활성 선택 버튼을 제공한다.
추가 상태와 실제 이미지 처리는 교수의 상태관리·실제 로직 감점 위험이 있으므로 점수 승인을 보증하지 않는다.

### 후기·Tag와 날짜별 제한 (A-11/B-8/B-9/C-8)

Tag는 모든 여행 상태에서 쉼표로 입력·수정·전체 삭제할 수 있다. 빈 값은 제거하고 같은 Tag는 한 번만 남긴다.
입력 길이는 Tag 전체 500자, 후기 2000자다. A는 기존 Tag 표시만 유지하며 후기는 표시하지 않는다.
B와 추억 카드에는 GET 또는 세션 후기와 모든 Tag를 줄 수 제한 없이 표시한다.

| 날짜 상태 | Tag 관리 | 후기 입력 | 추억 카드 생성/PNG |
|---|---|---|---|
| 미래 여행 | 가능 | 불가 | 불가 |
| 진행 중 (오늘 시작/오늘 종료 포함) | 가능 | 가능 | 불가 |
| 종료 (종료일 < 오늘) | 가능 | 가능 | 가능 |
| 날짜 미정/오류 또는 삭제됨 | Tag 폼은 유지 | 불가 | 불가 |

TripDates/tripStatus의 기존 날짜 비교를 공유하고 추가/편집 폼은 날짜 변경 즉시 후기 입력 가능 여부를 갱신한다.
후기가 있는 여행을 미래 날짜로 바꿔 저장하면 후기가 제거됨을 폼에서 고지한다. 저장 전 취소하면 원본이 유지된다.
카드 생성과 PNG 내보내기에서도 종료 상태를 확인하여 비활성 버튼 외 호출 경로도 막는다.

### C-8/C-9 추억 카드와 명시적 PNG 다운로드

C 전체 여행의 카드 만들기 버튼은 종료 여행만 활성화한다.
사진은 현재 여행의 첫 번째 사용자 사진을 우선 사용하고 사진이 없으면 기존 목적지 사진을 사용한다. B-6도 같은 Dialog를 사용한다.
새 독립 페이지 없이 RepaintBoundary 안에 기존 NetImage·Text·Wrap(Chip)로 전체 내용을 그린다.
미리보기는 스크롤할 수 있으며 PNG는 스크롤 밖의 카드 부분도 포함한다. 상태 안내와 버튼은 이미지에 포함하지 않는다.
Web에서 Flutter SDK의 toImage/PNG 인코딩과 브라우저 Blob 다운로드를 사용한다. 패키지·서버 API를 추가하지 않는다.
여행 JSON·후기·Tag는 영구 저장하지 않으며, 사용자가 직접 선택한 PNG 파일 다운로드만 예외로 허용한다.
원본 사진을 불러오지 못하면 기존 NetImage의 기본 표지/아이콘 대체가 카드와 PNG에도 그대로 보인다.
내보내기 중 중복 실행/닫기를 막고 실패 시 한국어 안내와 재시도를 제공한다. 완료 문구는 다운로드 요청 사실만 알린다.
기존 Web 데모를 지원 대상으로 하며 네이티브 Android/iOS/데스크톱의 파일 저장 연동은 추가하지 않는다.
네이티브 플랫폼에서는 미리보기를 유지하고 Web 다운로드 안내와 비활성 버튼을 표시한다.
카드의 최대 축은 8192px로 제한하고 긴 내용은 전체를 비율 축소하여 자르지 않는다.

## 9. 범위·개인정보·외부 서비스

별도 ProfileScreen을 제거하고 기존 A 아바타는 설명 모달로 처리한다. A/B/C 이외 독립 페이지는 없다.
로그인·회원가입·결제·개인정보 수집·유료 API·실시간 통신은 없다. PNG는 사용자의 명시적 다운로드 요청만 처리한다. 입력은 가상의 여행명·목적지·메모만 시연하며
서버/기기에 저장·전송하지 않으며 화면 세션 메모리에서만 변경한다. 공개된 예시 여행 데이터만 GET으로 읽는다. 사진 CDN 접근은 기존 고정 사진 표시만 담당한다.

## 10. 데이터·사진 자원과 시험 범위

destinations.json의 50개 도시·35개 국가와 기존 지역 자료, 확인된 고정 사진·라이선스는 보존한다.
앱 시작 시 asset을 읽고 검증하는 것은 표시 자원 로딩이며 외부 지오코딩/추천 API를 호출하지 않는다.
알 수 없는 사진은 중성 표지로 대체하고 실패 시 기존 이미지 아이콘을 사용한다.
테스트는 사진과 반응형 레이아웃·A/B/C 이동·Loading/Error/Empty·GET 오류 복구·검색·정렬·집계·별칭 인식·지도 Marker/가까운 도시 Dialog·세션 변경/복원과 GET 재조회 시 초기화를 확인한다.
기존 테스트 파일을 유지하고 서버 저장 대신 세션 전용 계약으로 갱신한다. 서버 쓰기 금지는 별도로 검증한다.

## 11. 교수 감점 규칙에 따른 남은 위험

| 규칙 | 현재 구현과 위험 |
|---|---|
| 실제 로그인·결제 | 구현하지 않음 |

기능을 보존하라는 사용자의 명시적 요청을 반영했다. 위험 기능을 임의로 삭제하거나 가짜 결과로 바꾸지 않는다.
실제 PPT/PDF·앱 리뷰·발표 영상은 제공되지 않아 최종 일치 여부를 확인할 수 없다.
별도 자가평가/셀프 논증 문서의 미작성 제출 증빙도 사람이 작성해야 한다. 통과 점수·교수 승인을 보증하지 않는다.

| 종료 | 숨김 | 불가 | 불가, 메모리 데이터는 유지 | 가능 |
| 날짜 오류/삭제 | 숨김 | 불가 | 불가 | 불가 |

오늘은 DateTime.now()의 로컬 연/월/일을 사용하며 UTC 날짜로 변환하지 않는다. 날짜 비교용 UTC 값도 이 로컬 연/월/일로 구성한다. 예: 여행 10/28~11/01, 로컬 오늘 10/31이면 DatePicker의 firstDate=10/31, lastDate=11/01이다. 이전 날짜는 선택할 수 없다. 종료일 당일은 그날만 선택 가능하고 다음 날부터 계획 영역을 숨긴다. 오늘의 시각이 이미 지났어도 날짜가 오늘이면 변경 가능하다.

계획의 원래 날짜가 과거라면 날짜를 미래로 바꾸는 편집도 허용하지 않는다. 과거 계획은 동일한 카드로 표시하되 보기 전용 표시와 함께 편집/삭제 버튼을 숨긴다. 새 계획/변경 결과는 여행 기간 및 오늘 하한을 모두 검사한다. 메모리 변경 콜백도 과거 항목이 원본 그대로 남아 있는지 검증하므로 지난 계획을 삭제/대체할 수 없다.

B/계획 카드/에디터는 매분 날짜 상태를 표시 갱신한다. 모든 변경 직전, picker 반환 후와 삭제 확인 후에도 최신 날짜를 검사한다. 편집 중 자정을 넘겨 원래 계획이 과거가 되면 저장을 막고 원본을 보존한다. 새 계획 초안의 날짜가 과거가 되면 저장 검증에서 거절하며 새 날짜 선택이 필요하다. 미래→진행 변경 자체는 편집을 막지 않는다.

### 선택기와 카드 디자인

B-12는 제목/태그 아래 날짜 그룹·개수·상태 안내·추가 버튼을 배치한다. 흰색 17dp 카드에 연한 녹색 AM/PM 시간 배지, 장소 아이콘/제목과 활동 본문을 표시한다. B-13의 DatePicker는 max(여행 시작일, 로컬 오늘)~종료일로 제한한다. TimePicker는 기기 설정과 무관하게 12시간제 AM/PM을 사용한다. 내부 시간은 HH:mm이며 전체 계획은 날짜/시간순, 같은 시각은 입력순으로 정렬한다. 자정 AM 12:00, 정오 PM 12:00 표기를 유지한다. 장소 100자·활동 500자, 공백 입력은 거절한다. 취소는 원본을 바꾸지 않고 삭제는 확인 Dialog를 거친다.

카드 420dp 이상은 시간/내용 가로 배치, 좁으면 세로 배치한다. 날짜/시간 선택 버튼은 380dp 이상에서 가로 배치한다. B는 데스크톱 최대 860dp 콘텐츠 폭, 모바일 18dp 여백을 유지한다. 기존 #183B3A/#2D7770/#687775, 원래 사진/썸네일/기록 디자인을 유지한다. 스크롤과 키보드 축소를 지원한다.

여행 기록은 기존 GET 3상태와 메모리 추가를 유지한다. 미래 여행은 추가 버튼을 숨기고 시작 후 가능하다는 안내를 표시한다. 진행/종료 여행만 추가할 수 있고 Dialog 열기 전·확인 시·비동기 적용 시 재검사한다.

### 추천 검색 (유지)

destinations.json의 기존 50개 도시 ID·별칭·국가·사진·좌표와 themes/keywords/countryNames(en/ko/zh)를 재사용한다. 별도 도시 DB·외부 API·추천 알고리즘은 없다. 도시 중한영 이름/별칭·국가 코드/중한영 국가명·테마/다국어 키워드를 공백 구분 AND 및 부분 일치로 검색한다. 전체/문화/자연/도시 필터와 함께 적용하고 50개 도시 사진·결과 수·지우기·빈 결과·기존 추가 폼 미리 입력/취소를 유지한다.

계획 CRUD·날짜 권한/정렬/입력 검증·검색은 사용자 요청으로 구현한 실제 세션 로직이다. 11절의 과제 감점 위험 설명이 적용되며 영구 저장·쓰기 API·추가 패키지는 없다.

## 13. 기록별 독립 사진과 타임라인

B-7은 기존 GET 로딩/오류/빈 상태와 재시도를 유지한다. 진행/종료 여행만 기록 추가 및 편집이 가능하고 미래/오류/삭제 여행은 읽기만 가능하다. 기록 목록의 위치는 기존 입력 순서를 유지한다. 새 기록은 로컬 작성 날짜와 시간을 표시하고 편집할 때 원래 작성 시각을 유지한다. GET의 예전 기록에 시간이 없거나 잘못되면 시간 미기록으로 표시한다.

Note.photo는 nullable Uint8List 단일 필드다. GET JSON의 photo는 무시하고 파일명/경로도 저장하지 않는다. 여행 상단 Item.photos, 표지/기본 사진을 참조하지 않으며 기록 사진을 상단 갤러리나 추억 카드로 복사하지 않는다. 각 기록은 자신의 사진만 표시한다. Note.time은 선택적 HH:mm 문자열이며 UI는 AM/PM이다.

B-14는 날짜·시간 배지·기록 본문·사진 순서의 흰색 20dp 카드다. 왼쪽 점/세로 연결선은 카드 전체 높이에 맞춰 사진과 긴 글에도 이어진다. 날짜/시간/편집은 Wrap으로 좁은 창에서 줄바꿈한다. 사진은 4:3, 15dp 모서리이며 사진이 없으면 공간을 차지하지 않는다. 이미지 오류 시 중립 아이콘을 쓰고 다른 여행 사진으로 대체하지 않는다. 데스크톱 최대 860dp, 모바일 18dp 여백과 기존 녹색 테마를 유지한다.

B-15는 아이콘/제목 → 작성 시각/설명 → 넉넉한 기록 입력 → 독립 사진 섹션/미리보기 → 추가·교체·삭제 → 세션 안내 → 취소/저장 순서다. 새 페이지 없이 기존 showDialog를 사용하고 작은 창/키보드에서 스크롤한다. 텍스트는 공백을 제외한 내용이 필요하며 사진은 선택이다. 편집 취소 시 텍스트/사진 삭제·교체도 모두 취소된다. 사진 삭제만 저장해도 본문/기록/시각은 유지한다.

사진 선택은 기존 Web 로컬 파일 선택기 및 prepareTripPhoto를 재사용한다. 한 번에 한 장(limit=1), 10MB/60MP 이하 소스, 긴 축 1920px 이하 정적 PNG로 변환한다. 다중 선택/손상/초과 파일/취소 시 기존 사진을 보존하고 오류를 표시한다. 원본 경로/EXIF는 보관하지 않는다. 원래 Web 지원 범위를 유지하며 네이티브는 사진 선택 불가 안내를 표시한다. 새 패키지는 없다.

선택·디코딩 전후와 기록 저장/반영 시 날짜 권한을 재검사한다. 선택 중 여행이 미래로 바뀌면 사진을 적용하지 않는다. 처리 중 중복 선택/삭제/저장/닫기를 막는다. 에디터는 매분 권한 안내를 갱신한다. 기록/사진은 기존 상세 페이지 메모리 범위로 유지되고 상세를 닫거나 GET 재조회/재실행하면 초기화된다. 서버 업로드·쓰기 API·브라우저 저장소·파일 쓰기는 없다. 과제의 실제 상태/로직 관련 위험 설명은 유지한다.
