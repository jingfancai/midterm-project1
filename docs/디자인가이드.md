# 디자인 가이드 — Polarsteps v2

> 사용자 제공 교수 원본의 1–5장 제목과 표 칸 이름/순서를 유지한다. 실제 앱 리뷰·캡처·영상·교수 승인 근거는 확인되지 않아 TODO로 표시한다. 코드 관찰과 설계 의도를 사용자 조사 근거로 대신하지 않는다.

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 나의 여행 목록 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/items` |
| B | 여행 상세 | `lib/screens/b_detail_screen.dart` | 쌓기(push/pop) — A 카드/C 전체 여행 행 | `/notes?itemId=` 기록 탭 |
| C | 여행 추억 카드 | `lib/screens/c_result_sheet.dart` | 덮기(modal) — A 기록 모아보기 | 없음; 세션 데이터 |

```text
A ──push/pop──▶ B [tab: 여행 정보 | 여행 기록]
A ──BottomSheet──▶ C ──시트 닫기 + push──▶ B (전체 여행 행)
A ──Dialog──▶ E 여행지 추천 ──닫기 + Dialog──▶ 여행 추가 폼
B/C ──Dialog──▶ 공통 추억 카드·템플릿
C Marker ──Dialog──▶ 선택 도시 개요 ──닫기──▶ C 지도
```

**E는 A 페이지의 부속 Dialog이며 독립 주 화면이 아니다.** 파일은 `lib/screens/e_recommendations_dialog.dart`다. 계획/기록 편집·삭제 확인·프로필 안내도 부속 모달이다. 지도 개요에서는 B로 이동하지 않는다. 전환은 push/pop·tab·modal만 사용한다. A는 LayoutBuilder의 창 폭 600dp 이상 격자, 미만 목록이다.

| 템플릿/내보내기 | 선택/다운로드 | C-8/9/10 · B-6 | `lib/travel_memory_card.dart _template/_export` |

여행/계획/여행 사진은 A 소유 공유 세션이고, 기록/독립 사진은 현재 B 상세 범위다. 초안 취소는 원본을 유지한다. 상세 재진입은 기록 GET 원본으로, GET 새로고침/재시작은 공유 세션 원본으로 복구한다. 파일/브라우저/DB 영구 저장과 서버 쓰기는 없다.

## 6. GET 전용 데이터와 메모리 상호작용

HTTP는 lib/api.dart의 GET /items, /notes?itemId=만 사용한다. mock_server도 읽기 전용 메모리 라우터다. 생성·편집·즐겨찾기·삭제·복원은 세션만 변경하고 새 여행은 음수 ID를 쓴다. 삭제 실행 취소는 일반 4초/접근성 10초다. 새로고침은 원본을 복구한다.

## 7. 여행 통계와 날짜 분류

TripDates/tripStatus로 미래·진행·종료·날짜 미정을 구분한다. 방문 집계/지도는 이미 시작한 유효한 미삭제 여행만 포함한다. 별칭은 도시 ID로 통합하며 Tokyo+Osaka는 2도시/1국가다. 지역은 도시 Marker가 아니며 기존 국가 집계 정책은 유지한다. 로컬 날짜 상태를 매분 갱신하는 타이머는 있으나 실시간 통신은 없다.

## 8. 검색·목적지·사진·지도 자원

A는 제목·날짜/목적지·Tag에 대해 공백 구분 AND 검색과 그룹 내 정렬을 한다. 목적지 인식은 JSON 별칭의 정확한 일치다. 기존 50도시/35국가와 지역 자료를 재사용한다. 목적지 사진은 고정 외부 URL이며 실패 시 중립 대체다. 지도는 번들 world_map.png/Natural Earth 육지 윤곽 및 로컬 좌표를 사용한다. 출처는 assets/images/README.md. 지도 1~8배 확대/드래그·초기화를 유지하며 선택 도시 하나의 개요만 표시한다.

## 9. 범위·개인정보·외부 서비스

로그인·결제·GPS·개인정보 수집·외부 추천/지도 API·실시간 통신·추가 상태관리 패키지는 없다. 기존 사진 CDN 접근과 GET 목업은 존재한다. 로컬 선택 사진은 메모리만 사용하며 수업 시연에는 합성/비개인 자료를 권장한다. 사용자 요청 PNG 다운로드는 명시적 파일 내보내기이고 자동 여행 데이터 저장과 구분한다.

## 10. 데이터·사진 자원과 시험 범위

테스트 코드에는 GET 3상태, 세션 초기화, 사진/날짜/도시 집계, 지도 개요, 계획 권한/진행률, 기록 사진/삭제, 템플릿 PNG와 반응형 회귀가 있다. 현재 환경은 Flutter SDK가 없어 전체 analyze/test/build를 실행하지 못했다. 통과를 주장하지 않으며 TODO: 실행 가능한 환경에서 버전·실제 결과·시연 증거 기록. 기존 prototype_contract_test.dart의 TODO 금지 단언은 이 요청의 미확인 근거 TODO 원칙과 충돌한다. 본 작업은 문서만 변경하므로 테스트는 그대로 두며 향후 별도 조정 필요.

## 11. 교수 감점 규칙에 따른 남은 위험

**위험 있음**: setState/콜백은 실제 상태관리이며 검색·정렬·날짜 권한/검증·통계·Marker 좌표·이미지 변환·PNG 렌더링은 실제 로직이다. 서버 쓰기/영구 저장/유료 API가 없어도 과제 감점을 모두 피한다고 주장할 수 없다. PNG 다운로드도 교수 해석에 따른 위험이 있다. TODO: 발표자료·실제 리뷰·사용자 검증·교수 판단 근거 보완. 승인/점수는 보증하지 않는다.

## 12. B 여행 계획 · A 부속 여행지 추천

계획은 B의 미래/진행 여행에만 표시한다. 미래 DatePicker는 전체 여행 기간, 진행 중은 로컬 오늘~종료일이다. 지난 계획 내용 변경/삭제는 금지하고 진행 중 완료만 변경 가능하다. 종료 여행에서는 영역을 숨기되 메모리 원본은 유지한다. AM/PM TimePicker, 시간순/동시간 입력순 정렬, 장소 100자·활동 500자 검증을 유지한다. 선택기 반환/저장/삭제 및 메모리 콜백에서 재검사하고 과거 계획 식별자/내용을 보존한다. E는 A 부속 Dialog: 전체/문화/자연/도시 필터와 중한영 도시/국가/테마/키워드 검색을 조합해 기존 추가 폼을 미리 채운다. 취소 시 생성하지 않는다.

## 13. 기록별 독립 사진과 타임라인

진행/종료 여행만 기록 추가·편집·삭제가 가능하다. 새 기록은 로컬 날짜/시각을 갖고 수정 시 보존한다. 옛 시각이 없으면 미기록 표시한다. Note.photo 한 장은 상단 Item.photos와 독립적이며 JSON의 사진은 무시한다. 취소/손상/다중 선택은 기존 사진을 보존한다. 사진은 기존 Web 선택기·prepareTripPhoto로 10MB/60MP 이하 입력을 긴 축 1920px 이하 정적 PNG로 변환한다. 여행 상단 사진은 최대 5장, 기록은 최대 1장이다. 이름/경로/EXIF는 보관하지 않는다. 선택/디코딩 전후와 저장 때 권한을 재검사한다. 네이티브에는 선택 불가 안내를 제공한다.

## 14. 삭제 · 지도 개요 · 완료 · 카드 템플릿

기록 삭제는 확인 후 해당 기록/사진만 제거하고 마지막 삭제 시 빈 상태다. 지도 Marker는 현재 도시의 여행 제목·날짜·장소·태그만 표시한다. 겹친 터치 영역은 가장 가까운 점으로 해석하고 상세 이동은 하지 않는다. C 전체 여행 행의 B 이동은 별도 유지한다. 계획 completed는 미래/진행 여행만 변경하며 0/0 및 완료/총수 진행률을 제공한다. 종료 여행만 생성하는 추억 카드는 심플/엽서/사진 콜라주 3종이다. 기존 사진 최대 5장을 재사용하며 1장/0장은 단일/기본 사진으로 대체하고 이미지를 복제해 채우지 않는다. 선택된 동일 RepaintBoundary를 전체 PNG로 캡처하며 컨트롤은 제외한다. 최대 축 8192px로 비율 축소하고 precache·잠금·실패 재시도를 유지한다. Web 내보내기, 네이티브 미리보기 범위를 따른다.
