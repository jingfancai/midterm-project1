# 원칙 카드 (5칸) [권장]

> 고친 원칙마다 한 장. 다섯 칸을 모두 채우면 기획 · 코드 · 영상 · 셀프 논증 기록이 같은 번호로 이어집니다.
> P번호 = 닐슨 원칙 번호. 발표 자료 부록(원칙 카드 전부)에 그대로 옮깁니다.
> '판단' 칸은 셀프 논증 기록의 "내 주장 → 반론 → 재반론 → 결론 → 근거"를 줄여 쓴 것입니다.

## 빈 양식 — 복사해서 P번호마다 한 장

### 원칙 카드 P__

| 칸 | 내용 |
|---|---|
| **원칙** | 닐슨 원칙 번호 · 이름 |
| **근거** | 현행 앱에서 찾은 위반 또는 잘된 점 — 리뷰 인용(날짜 · 별점, **작성자 이름 지움**) · 캡처 |
| **적용** | v2 화면 이름 · 요소 번호 · Flutter 위젯명 · 비즈니스 명칭 · 코드 주석 `// P__` |
| **시연** | 전 · 후 캡처 또는 5–10초 클립 `docs/영상/p__.mp4` |
| **판단** | 고려했지만 고르지 않은 대안 → 버린 이유 (원칙 · 리뷰 근거) |

## 채운 예시 — 이 템플릿의 화면 A (지우고 내 카드로 바꾼다)

### 원칙 카드 P09

| 칸 | 내용 |
|---|---|
| **원칙** | 닐슨 9 — 사용자가 오류를 알아보고 · 진단하고 · 복구하도록 돕는다 |
| **근거** | (설명용 예시) "목록이 안 떠서 뭘 해야 할지 몰랐다" 류의 리뷰 — 실제 과제는 원문 · 날짜 · 별점으로 인용 |
| **적용** | 화면 A A-5 · `ErrorView` + `FilledButton` · "오류 안내 · 다시 시도" — `a_list_screen.dart`의 `// A-5 P09` |
| **시연** | `p09.mp4` — `--dart-define=DEMO_STATE=error`로 실행 → 오류 안내 → 다시 시도 |
| **판단** | SnackBar(잠깐 뜨는 알림)로만 알리기 — 버림: 몇 초 뒤 사라져 다시 시도할 길이 화면에 남지 않는다 |

## 여행 관리 확장 — 구현 근거

| 원칙 | 적용 | 판단·검증 |
|---|---|---|
| P01 시스템 상태의 가시성 | A-10 전체 여행 통계, A-8 표시 개수 | 검색 결과와 전체 통계를 구별하고 삭제·복원 시 갱신을 테스트한다. |
| P03 사용자 통제와 자유 | A-9 삭제 실행 취소·즐겨찾기 해제 | 삭제를 확인한 뒤에도 동일한 서버 ID로 복원할 수 있다. |
| P05 오류 예방 | A-9 삭제 확인 다이얼로그 | 여행 이름과 세션 한정 삭제임을 표시하고 취소를 기본 선택지로 제공한다. |
| P07 사용의 유연성과 효율성 | A-7 검색·A-8 필터·그룹 내 정렬 | 제목·목적지·태그를 함께 검색하고 필터와 조합한다. 결과 없음에서 초기화할 수 있다. |

위 근거는 이번 사용자 요청과 구현 동작에 관한 것이다. 실제 사용자 리뷰나 시연 영상 근거를 새로 수집한 것은 아니다.

## 영구 저장 확장

- P01: 저장 완료 후 홈·상세·통계를 함께 갱신하며 서버에서 즐겨찾기와 삭제 상태를 다시 읽는다.
- P05: B-8은 필수 정보·ISO 국가 코드·실제 날짜·종료일 순서를 검사한다. 저장 중 중복 작업을 차단한다.
- P09: 서버 쓰기 실패 시 기존 데이터와 편집 입력을 유지하며 오류를 표시한다. 소프트 삭제와 서버 복원으로 연관 여행 기록을 보존한다.
- 검증: Flutter API/위젯 회귀 테스트 및 임시 DB로 수행하는 실제 json-server 재시작 테스트. 새로운 사용자 리뷰나 동영상 근거를 수집한 것은 아니다.
